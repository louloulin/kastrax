# kastrax-code模块修复计划

## 异常分类与修复计划

通过执行`gradle build -x test`命令，我们发现kastrax-code模块存在大量编译错误。为了有效地解决这些问题，我们将异常分为以下几类，并制定相应的修复计划：

### 1. 日志相关异常

**问题描述**：
- 大量类中存在`Cannot access class 'mu.KLogger'`错误
- 大量类中存在`Unresolved reference 'info'`、`Unresolved reference 'debug'`、`Unresolved reference 'error'`等错误
- 日志库依赖冲突，Kotlin日志库与IntelliJ平台日志库混用

**修复计划**：
1. 移除Kotlin日志库依赖（io.github.oshai:kotlin-logging-jvm）
2. 在build.gradle.kts中添加IntelliJ平台日志依赖
3. 修改所有使用KLogger的类，改为使用IntelliJ平台的Logger类
4. 统一日志调用方式，从字符串模板形式（`logger.info { "消息" }`）改为直接调用（`logger.info("消息")`）
5. 在KastraXCodeBase类中提供统一的logger实现，供所有子类使用

### 2. IntelliJ平台API相关异常

**问题描述**：
- 无法解析IntelliJ平台相关类，如`DataManager`、`EditorFactory`、`FileTypeManager`等
- 无法解析IntelliJ平台相关方法，如`findFileTypeByName`、`isLineNumbersShown`等
- 无法解析IntelliJ平台相关属性，如`settings`、`component`等

**修复计划**：
1. 在build.gradle.kts中添加正确的IntelliJ平台依赖
2. 使用IntelliJ Platform Gradle Plugin配置插件项目
3. 添加必要的插件依赖声明，如`com.intellij.modules.platform`、`com.intellij.modules.lang`等
4. 参考kastrax-codex模块的依赖配置，确保依赖版本一致

### 3. UI组件相关异常

**问题描述**：
- 类型不匹配问题，如`Type argument is not within its bounds`
- 参数类型不匹配，如`Argument type mismatch: actual type is 'java.awt.BorderLayout', but 'java.awt.LayoutManager' was expected`
- 无法解析UI组件，如`JBPanel`、`JBLabel`、`JBColor`等
- 模拟类与真实类之间的类型不匹配，如`Argument type mismatch: actual type is 'ai.kastrax.code.mock.Project', but 'com.intellij.openapi.project.Project' was expected`

**修复计划**：
1. 移除模拟UI组件类，直接使用IntelliJ平台提供的UI组件
2. 修改UI组件的使用方式，确保类型参数正确
3. 修复布局管理器的使用，确保参数类型匹配
4. 参考kastrax-codex模块的UI实现，使用相同的组件和布局方式

### 4. 模型类相关异常

**问题描述**：
- 无法解析`LLMRequest`、`LLMResponse`等类
- 无法解析`llmProvider`、`process`等方法
- 无法解析`type`、`name`、`content`等属性
- 参数名称不匹配，如`No parameter with name 'input' found`、`No parameter with name 'metadata' found`

**修复计划**：
1. 创建或修复模型类，确保它们具有正确的属性和方法
2. 统一模型类的命名和结构，避免混淆
3. 修复方法参数，确保参数名称匹配
4. 参考kastrax-core模块的模型类实现，确保兼容性

### 5. 依赖解析异常

**问题描述**：
- 无法解析IntelliJ Platform依赖，如`com.intellij.platform:ui-impl:241.14494.240`
- 缺少正确的IntelliJ Platform SDK配置
- 依赖版本冲突

**修复计划**：
1. 使用IntelliJ Platform Gradle Plugin配置插件项目
2. 添加正确的IntelliJ IDEA版本依赖，如`intellij { version = "2023.3" }`
3. 配置正确的插件依赖，如`plugins = listOf("com.intellij.java")`
4. 统一依赖版本，避免版本冲突

## 修复优先级

根据问题的严重性和影响范围，我们将按以下优先级进行修复：

1. **日志相关异常**：这是最基础的问题，影响了几乎所有类，应该首先解决
2. **依赖解析异常**：解决依赖问题是后续修复的基础
3. **IntelliJ平台API相关异常**：这些异常影响了核心功能的实现
4. **模型类相关异常**：这些异常影响了业务逻辑的实现
5. **UI组件相关异常**：这些异常主要影响界面展示，可以最后解决
