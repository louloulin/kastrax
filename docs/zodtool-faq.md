## 基本概念

### ZodTool 与传统 Tool 有什么区别？

ZodTool 是传统 Tool 的类型安全版本。主要区别在于：

1. **类型安全**：ZodTool 使用泛型参数指定输入和输出类型，提供编译时类型检查。
2. **模式定义**：ZodTool 使用 kastrax-zod 模式定义输入和输出，而不是 JSON Schema。
3. **验证能力**：ZodTool 提供更强大的验证和转换能力。
4. **错误处理**：ZodTool 提供更详细和更有用的错误消息。

### 为什么要使用 ZodTool 而不是传统 Tool？

使用 ZodTool 的主要优势包括：

1. **类型安全**：减少运行时错误，提高代码可靠性。
2. **开发体验**：更好的 IDE 支持和代码补全。
3. **验证能力**：更强大的数据验证和转换能力。
4. **错误处理**：更详细和更有用的错误消息。
5. **可维护性**：更清晰的代码结构和更好的文档。

### 如何在现有项目中引入 ZodTool？

在现有项目中引入 ZodTool 的最佳方法是逐步迁移：

1. 首先，确保项目依赖于 kastrax-core 和 kastrax-zod 模块。
2. 对于新的工具，直接使用 ZodTool。
3. 对于现有的工具，可以使用 `toZodTool` 方法将其转换为 ZodTool。
4. 或者，可以使用 `zodToolAsLegacy` 函数创建与传统 Tool 兼容的工具。

详细的迁移指南请参考 [迁移到 ZodTool](migrating-to-zodtool.md)。

## 设计与架构

### ZodTool 的内部实现原理是什么？

ZodTool 的内部实现基于以下原则：

1. **类型安全**：使用泛型参数指定输入和输出类型。
2. **模式验证**：使用 kastrax-zod 模式验证输入和输出。
3. **转换层**：在 JSON 和类型化对象之间提供转换层。
4. **向后兼容**：提供与传统 Tool 的互操作性。

具体实现包括：

- `ZodTool` 接口定义了工具的基本属性和方法。
- `ZodToolBuilder` 类提供了构建 ZodTool 实例的 DSL。
- `toTool` 方法将 ZodTool 转换为传统 Tool。
- `toZodTool` 方法将传统 Tool 转换为 ZodTool。

### 如何处理复杂的数据结构？

ZodTool 可以处理各种复杂的数据结构：

1. **嵌套对象**：使用 `objectInput` 和 `objectField` 创建嵌套对象。
2. **数组**：使用 `arrayInput` 和 `arrayField` 创建数组。
3. **映射**：使用 `objectInput` 和 `catchall` 创建映射。
4. **联合类型**：使用 `unionInput` 创建联合类型。
5. **可选字段**：使用 `required = false` 参数创建可选字段。
6. **默认值**：使用 `default` 方法设置默认值。

详细示例请参考 [ZodTool 高级用法指南](advanced-zodtool-usage.md)。

### 如何处理循环依赖问题？

kastrax-core 和 kastrax-zod 模块之间存在循环依赖问题。解决这个问题的方法包括：

1. **创建公共模块**：将共享的接口和类移动到一个公共模块中。
2. **使用依赖注入**：使用依赖注入或其他设计模式来打破循环。
3. **重构模块结构**：重新设计模块结构，消除循环依赖。

在实际使用中，您只需要依赖 kastrax-core，它会自动包含 kastrax-zod。

## 性能与优化

### ZodTool 的性能如何？

ZodTool 的性能与传统 Tool 相当，但在某些情况下可能会有轻微的性能开销，主要是由于额外的类型转换和验证。然而，这种开销通常是可以接受的，特别是考虑到 ZodTool 提供的类型安全和验证能力。

### 如何优化 ZodTool 的性能？

优化 ZodTool 性能的方法包括：

1. **重用模式**：定义一次模式，多处使用，避免重复创建。
2. **延迟验证**：只在需要时验证特定字段，而不是验证整个对象。
3. **减少转换**：尽量减少在 JSON 和类型化对象之间的转换。
4. **使用简单类型**：尽可能使用简单类型，避免复杂的嵌套结构。
5. **缓存结果**：缓存验证和转换结果，避免重复计算。

详细的性能优化建议请参考 [ZodTool 高级用法指南](advanced-zodtool-usage.md#性能优化)。

### ZodTool 是否适合高性能应用？

ZodTool 适合大多数应用场景，包括中等规模的高性能应用。对于极端高性能要求的场景，可以考虑以下策略：

1. **选择性验证**：只在关键点验证数据，而不是每次操作都验证。
2. **使用简化模式**：对于性能关键路径，使用简化的模式定义。
3. **预编译模式**：在应用启动时预编译模式，避免运行时编译开销。
4. **批处理验证**：对于批量操作，一次验证多个对象，而不是逐个验证。

## 错误处理

### 如何处理验证错误？

处理验证错误的最佳方法是使用 `safeParse` 方法：

```kotlin
val result = schema.safeParse(input)
when (result) {
    is SchemaResult.Success -> {
        // 处理成功情况
        val data = result.data
        // ...
    }
    is SchemaResult.Failure -> {
        // 处理失败情况
        val error = result.error
        // 显示错误消息或记录日志
        println("验证失败: $error")
    }
}
```

### 如何自定义错误消息？

自定义错误消息的方法包括：

1. **使用 `refine` 方法**：提供自定义错误消息。

```kotlin
val ageSchema = numberInput("Age")
    .refine({ age -> age >= 18 }, "您必须年满 18 岁")
```

2. **使用 `superRefine` 方法**：提供更详细的错误处理。

```kotlin
val passwordSchema = stringInput("Password")
    .superRefine { password, ctx ->
        if (password.length < 8) {
            ctx.addIssue("密码长度必须至少为 8 个字符")
        }
        // 更多验证...
    }
```

### 如何在工具执行过程中处理错误？

在工具执行过程中处理错误的最佳方法是使用 try-catch 块：

```kotlin
val myTool = zodTool<String, String> {
    // ...
    execute = { input ->
        try {
            // 执行可能失败的操作
            processInput(input)
        } catch (e: Exception) {
            // 处理异常
            "处理输入时出错: ${e.message}"
        }
    }
}
```

对于更复杂的错误处理，可以考虑使用 Result 类型或自定义错误类型。

## 故障排除

### 为什么我的模式验证失败？

模式验证失败的常见原因包括：

1. **类型不匹配**：输入类型与模式定义不匹配。
2. **缺少必填字段**：缺少模式中定义的必填字段。
3. **验证规则失败**：输入不满足模式中定义的验证规则。
4. **格式错误**：输入格式不正确，例如无效的电子邮件或 URL。
5. **嵌套对象错误**：嵌套对象中的字段验证失败。

要诊断验证失败，请检查 `SchemaResult.Failure` 中的错误消息，它通常会提供详细的错误信息。

### 为什么我的工具执行失败？

工具执行失败的常见原因包括：

1. **输入验证失败**：输入不满足模式定义。
2. **执行逻辑错误**：工具执行逻辑中的错误。
3. **外部依赖失败**：工具依赖的外部服务或资源不可用。
4. **权限问题**：缺少执行工具所需的权限。
5. **资源限制**：超出资源限制，例如内存或 CPU 限制。

要诊断执行失败，请检查异常堆栈和日志，它们通常会提供详细的错误信息。

### 如何解决循环依赖问题？

解决循环依赖问题的方法包括：

1. **创建公共模块**：将共享的接口和类移动到一个公共模块中。
2. **使用依赖注入**：使用依赖注入或其他设计模式来打破循环。
3. **重构模块结构**：重新设计模块结构，消除循环依赖。
4. **使用接口**：使用接口而不是具体实现，减少直接依赖。
5. **延迟加载**：使用延迟加载或懒加载技术，避免循环依赖。

在实际使用中，您只需要依赖 kastrax-core，它会自动包含 kastrax-zod。
