# Dataflare UI Rule 节点功能实现计划

## 概述

本文档概述了 Dataflare UI 中规则引擎节点的实现计划，基于对 Datalink UI 中现有规则节点的分析。规则引擎节点是可视化规则编辑器的核心组件，允许用户通过拖放和配置节点来创建和编辑业务规则。

## 已实现的节点类型

目前，Dataflare UI 已经实现了以下规则节点类型：

1. **StartNode** - 规则流程的起始节点
2. **EndNode** - 规则流程的结束节点
3. **ConditionNode** - 条件判断节点，支持两个输出路径（真/假）
4. **ActionNode** - 执行动作的节点，如日志记录、消息发送等
5. **TransformNode** - 数据转换节点，支持字段映射和数据格式转换
6. **ScriptNode** - 脚本执行节点，支持运行自定义脚本
7. **ApiNode** - API调用节点，支持HTTP请求
8. **DelayNode** - 延迟执行节点，在流程中引入延迟
9. **ResourceNode** - 资源连接节点，用于连接外部资源如数据库、文件等

## 节点实现模式

每个节点组件遵循以下通用模式：

### 共同特征

1. **使用 React.memo 优化性能**：避免不必要的重新渲染
2. **标准属性接口**：`id`, `data`, `selected` 等 ReactFlow 核心属性
3. **点击配置功能**：节点点击后可打开配置面板
4. **可视化状态反馈**：选中状态显示高亮边框
5. **连接点处理**：根据节点类型定义输入/输出连接点

## 各节点详细实现

### 1. StartNode

- **功能**：标记流程的开始点
- **特点**：只有输出连接点，无输入
- **配置项**：基本信息（标签）
- **已完成**：✅

### 2. EndNode

- **功能**：标记流程的结束点
- **特点**：只有输入连接点，无输出
- **配置项**：基本信息（标签）
- **已完成**：✅

### 3. ConditionNode

- **功能**：条件判断，根据表达式结果选择不同路径
- **特点**：
  - 一个输入连接点
  - 两个输出连接点（true/false）
- **配置项**：
  - 条件表达式（JavaScript表达式）
- **已完成**：✅

### 4. ActionNode

- **功能**：执行预定义的动作
- **特点**：
  - 标准的输入和输出连接点
  - 支持配置动作参数
- **配置项**：
  - 动作名称
  - 动作参数（JSON格式）
- **已完成**：✅

### 5. TransformNode

- **功能**：数据转换，字段映射
- **特点**：
  - 标准的输入和输出连接点
  - 显示映射字段数量
- **配置项**：
  - 转换类型
  - 字段映射（JSON格式）
- **已完成**：✅

### 6. ScriptNode

- **功能**：执行自定义脚本
- **特点**：
  - 标准的输入和输出连接点
  - 可选择已存在的脚本
- **配置项**：
  - 脚本选择
  - 脚本参数（JSON格式）
  - 超时设置
- **已完成**：✅

### 7. ApiNode

- **功能**：发送HTTP请求
- **特点**：
  - 标准的输入和输出连接点
  - 支持不同的HTTP方法
- **配置项**：
  - URL
  - 方法（GET, POST, PUT, DELETE, PATCH）
  - 请求头
  - 请求体
  - 超时设置
- **已完成**：✅

### 8. DelayNode

- **功能**：流程延迟
- **特点**：
  - 标准的输入和输出连接点
  - 显示延迟时间
- **配置项**：
  - 延迟时间（毫秒）
- **已完成**：✅

### 9. ResourceNode

- **功能**：连接外部资源
- **特点**：
  - 标准的输入和输出连接点
  - 根据资源类型调整配置选项
- **配置项**：
  - 资源选择
  - 查询类型（SQL/API）
  - 查询内容
- **已完成**：✅

3. **扩展性**：
   - 实现节点插件系统，允许第三方开发者扩展节点类型
   - 支持自定义节点样式和布局

4. **集成增强**：
   - 与资源管理系统的深度集成
   - 规则测试和调试功能

## 实现注意事项

1. **状态管理**：节点状态应与规则编辑器的全局状态同步，确保配置更改即时反映
2. **一致性**：所有节点应遵循一致的设计模式和样式指南
3. **可访问性**：确保所有节点和配置对话框符合可访问性标准
4. **国际化**：支持多语言，将界面文本与代码分离
5. **移动端支持**：考虑在移动设备上的使用体验

## 结论

通过实现上述节点类型和功能，Dataflare UI 的规则引擎将能够支持复杂的业务规则配置。已完成的节点覆盖了基本的流程控制、数据处理和系统交互功能，为用户提供了一个功能完备的可视化规则编辑器。
